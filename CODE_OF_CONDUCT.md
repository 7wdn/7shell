# Code of conduct

## In short

Be decent. This project welcomes people who want to build a good tool together, and it is not
the place for personal attacks, harassment, or arguments about who is allowed to be here.

## What is expected

- Assume the other person is competent and acting in good faith, especially when they disagree
  with you. Ask what they are optimizing for; it is usually something you cannot see from the diff.
- Critique the work, not the person. "This loses the error's cause" is useful. "This is
  amateurish" is not.
- Accept that maintainers make the final call on scope, naming and direction, and say so plainly
  when you disagree — once, with reasons. Repeating it in four threads is not persuasion.
- Security reports go through the process in [SECURITY.md](SECURITY.md), not into public issues.
- Write in whatever language you are comfortable in. The project keeps its documentation and
  interface in English and Chinese; a question in either, or in another language with a
  translator attached, is a valid question.

## What is not accepted

Harassment, insults, discriminatory language, sustained disruption, sexualized attention of any
kind, publishing someone's private information, and deliberately making the project hostile to
newcomers. This applies in issues, pull requests, commit messages, code comments and any space
where someone is representing the project.

## If something happens

Report it privately to the maintainers — through a private security advisory on the repository if
you are not sure where else to send it. Reports are read by maintainers only. Responses range
from a private word to a permanent ban, depending on severity and pattern, and the person
reporting will be told what was decided.
